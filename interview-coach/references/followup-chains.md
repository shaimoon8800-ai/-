# 追问链设计法

## 面试官的真实套路

面试不是"一问一答"，是**连环追问**。面试官用追问验证三件事：

```
1. 这件事真是你做的吗？（验证真实性）
2. 你想清楚了吗？（验证深度）
3. 换个条件你还能应对吗？（验证迁移能力）
```

## 追问的三个方向

| 方向 | 追问什么 | 示例 |
|---|---|---|
| **要证据** | 数据口径、原始材料、他人评价 | "这个 30% 是怎么算的？" |
| **要归因** | 为什么、什么原因、怎么发现的 | "除了你说的原因，还有别的可能吗？" |
| **要反事实** | 如果换个条件会怎样 | "如果预算减半，你会怎么做？" |

## 追问链设计模板

对每一道题，设计 2 层纵深：

```
【表层问题】
你的项目效果怎么样？

【追问 1 · 要证据】
- 这个数据是你做的还是团队做的？
- 具体怎么统计的？口径是什么？
- 有没有当时的截图/文档？

【追问 2 · 要反事实】
- 如果当时没有这个资源，你会怎么做？
- 如果重做一次，哪里会不一样？
```

## 按问题类型的追问链

### 行为类（讲一次经历）

```
表层：讲一次你解决难题的经历
 ├─ 追问 1：这个难题里，最难的点具体在哪？
 ├─ 追问 2：你考虑过哪些方案？为什么选这个？
 └─ 追问 3：如果这个方案失败了，你的 plan B 是什么？
```

### 数据类（讲一个指标）

```
表层：你说转化率提升了 20%，怎么提升的？
 ├─ 追问 1：提升前的基线是多少？怎么确定的？
 ├─ 追问 2：有没有可能是季节性或大盘因素？
 └─ 追问 3：同期其他渠道是什么情况？
```

### 决策类（讲一个选择）

```
表层：为什么选 A 方案？
 ├─ 追问 1：B 方案的问题在哪？
 ├─ 追问 2：这个决策的前提条件是什么？前提变了怎么办？
 └─ 追问 3：谁反对过？你怎么处理的？
```

### 管理类（带团队）

```
表层：你怎么带团队的？
 ├─ 追问 1：带过最难带的人是什么样的？怎么处理？
 ├─ 追问 2：你怎么给下属反馈负面评价？
 └─ 追问 3：团队有人和你意见不合，你怎么处理？
```

### 失败类（挫折）

```
表层：讲一次失败的经历
 ├─ 追问 1：失败的根本原因是什么？（不要只说"经验不足"）
 ├─ 追问 2：你从什么时候意识到不对劲的？
 └─ 追问 3：如果重来，你在哪个节点会做不同的选择？
```

## 追问的"压力测试"设计

适当加一两个**压力题**，模拟真实面试中的不友好时刻：

| 压力型追问 | 考察 |
|---|---|
| "我觉得你这个做法有问题。" | 抗压与坚持 |
| "这个成果跟你关系不大吧？" | 是否心虚 |
| "你说的这些，感觉谁都能做。" | 差异化认知 |
| "如果我说这个方案不可行呢？" | 应变与说服 |

**注意**：压力测试是陪练的一部分，但要提醒用户——真实面试中遇到这类问题，**保持事实与逻辑，不卑不亢**，不需要为了赢而编造。

## 追问链的输出格式

```markdown
【Q3】转化率提升 20%，具体怎么做到的？

考察意图：验证数据真实性 + 归因能力
回答框架：结论先行 → 定位问题 → 做了什么 → 数据 → 归因
取材建议：用简历里「XX 项目」的经历
避坑：不要只讲"我们做了 A/B 测试"，要讲你的判断与取舍

追问链：
 ├─ 追问 1（要证据）：这个 20% 的基线怎么确定的？
 │   └─ 你要准备：改动前的数据、统计周期、样本量
 └─ 追问 2（要反事实）：如果这个改动没效果，你当时的备选是什么？
     └─ 你要准备：当时讨论过的其他方案
```

## 用户复盘时的三个提醒

1. **追问不过去的地方，就是准备不足的地方**——记下来重点补
2. **能答上来但答得啰嗦**，说明自己也没想清楚
3. **讲不出"如果重来会怎么改"**，说明这段经历只是执行，没有思考
