# 亮点挖掘法：动作 → 影响 → 证据

## 核心公式

```
做了什么（动作）+ 带来什么（影响）+ 用什么证明（证据）
```

大多数人的问题是**只写了动作**，没写影响和证据。

## 三种挖掘路径

### 路径 1：从"完成了什么"挖影响

| 只写动作 | 加上影响 | 加上证据 |
|---|---|---|
| 优化了接口 | 提升了系统响应速度 | 平均响应时间从 800ms 降到 120ms |
| 做了用户调研 | 明确了产品方向 | 20 位访谈产出 3 个方向，2 个已排期 |
| 整理了文档 | 降低新人上手成本 | 12 份散文档合并为 1 份手册，上手时间 3 天→1 天 |
| 跟进了客户 | 提升了复购 | 30 家客户回访，复购率从 40% 提到 55% |

### 路径 2：从"琐碎工作"挖价值

很多工作看起来琐碎，但可以挖出价值：

| 琐碎工作 | 挖法 |
|---|---|
| 每天回客户咨询 | 整理了 20 条高频问题，做成标准话术，团队回复效率提升 40% |
| 反复改需求 | 梳理出需求变更的 3 类根因，推动建立了变更评审流程 |
| 帮同事排查问题 | 沉淀了 8 个常见问题的排查手册，同类问题平均解决时间从 2 小时降到 20 分钟 |
| 整理会议记录 | 从 3 个月会议记录里提炼出 5 个反复出现的阻塞点，推动 A 流程优化 |

**挖掘角度**：是否降低了别人的成本？是否沉淀成了资产？是否避免了重复出错？

### 路径 3：从"失败/延期"挖改进

失败也可以写，关键在**归因和改进**：

```
❌ 项目延期了。
✅ 项目延期 5 天。根因是上游数据交付延迟（非本组可控），
   已推动建立数据交付 SLA；同时我方增加 1 名人力，
   后续阶段预计可追回 3 天。
```

## 量化四来源（按可用性排序）

1. **时间**：耗时、周期、提前/延后天数
2. **规模**：数量、覆盖范围、参与人数
3. **幅度**：百分比、倍数、排名变化
4. **金额**：收入、成本、节省

**四类都没有时**：写清**具体做了什么**（事项数、产出物），并把缺口标为 `【请补：数据】`。

## 三个绝对不要

| 不要 | 原因 |
|---|---|
| 编造数字 | 一旦被核对，全盘可信度归零 |
| 把团队成果写成个人成果 | 背调/同事评价会暴露，代价极高 |
| 用"大概""差不多" | 领导会认为你没有掌握自己的业务数据 |

## 自检：你的成果能被追问三层吗

对每条成果自问：

```
1. 这个结果，是你做的还是团队做的？（贡献边界）
2. 这个数字怎么算出来的？（口径）
3. 如果重做一次，你会改什么？（反思）
```

三层都能答上来，才算真正理解自己的成果。答不上来，说明这条别写得太满。

## 亮点排序原则

汇报里的成果**按影响大小排序**，不按时间顺序。

```
❌ 按时间：1 月做了 A，2 月做了 B，3 月做了 C
✅ 按影响：B（带来 30% 增长）> A（效率提升）> C（常规维护）
```

领导只读前三条，把最重要的放前面。
