# Excel 数据急救包

拿到一张烂表的正确反应不是硬着头皮做，而是**先体检再动手**。本 Skill 把"这张表能不能用"变成一个可回答的问题。

## 什么时候用

- 用户给了一份 CSV / Excel，说"帮我看看这数据""整理一下""做个分析"
- 用户要清洗数据：去重、补空、统一格式、拆分列
- 用户要做透视表但不知道从哪下手
- 用户要选图表但不确定哪种合适

**数据超过 5 万行时**先提示：脚本能处理，但要提醒用户注意耗时。

## 工作流（四步）

### 第 1 步 · 体检（不修改数据）
运行 `scripts/profile_data.py`：

```bash
python3 scripts/profile_data.py --input 数据.csv --out 体检报告.md
```

产出每列画像：

| 指标 | 说明 |
|---|---|
| 类型 | 数值 / 文本 / 日期 / 混合 |
| 缺失率 | 空值占比（>30% 要预警） |
| 唯一值 | 去重后的取值个数 |
| 疑似主键 | 唯一值 = 总行数且无缺失 |
| 异常 | 数值越界、日期早于 1900、前后空格、全角半角混杂 |

### 第 2 步 · 出问题清单
按 `references/data-cleaning-rules.md` 把问题分三级：

- 🔴 **阻断级**：无主键、关键列缺失率 >50%、表头缺失 → 必须先解决
- 🟡 **影响分析**：重复行、数值列混入文本、日期格式不统一
- 🟢 **美化级**：前后空格、大小写不一、列名不规范

**先把清单给用户确认，再动手改。** 清洗是不可逆的（除非有备份），不能自作主张。

### 第 3 步 · 清洗
运行 `scripts/clean_data.py`：

```bash
python3 scripts/clean_data.py --input 数据.csv --out 清洗后.xlsx --rules 规则.json
```

默认执行（可关）：

| 动作 | 说明 |
|---|---|
| 去重 | 完全相同行去重；保留首次出现 |
| 去空白 | 所有文本列 strip，全角转半角 |
| 类型修复 | 数值列里的 "1,234" / "¥123" 转成数字 |
| 日期归一 | 2026/1/5、2026-01-05、20260105 → `2026-01-05` |
| 空值标记 | 不擅自填充，标记出来让用户决策 |

**绝不擅自做的事**：删除行、修改数值、填充缺失值、合并列——这些都要用户明确同意。

### 第 4 步 · 分析建议
按 `references/pivot-guide.md` 与 `references/chart-selection.md` 给出：

1. **透视表建议**（3 组）：行维度 / 列维度 / 值字段 / 聚合方式
2. **图表建议**（2-3 个）：图表类型 + 为什么选它 + 要注意什么
3. **分析结论**：从数据里能看出什么（基于真实数字，不编）

## 输出交付物

1. `体检报告.md`（字段画像 + 问题清单）
2. `清洗后.xlsx`（含"原始数据"和"清洗后"两个 sheet，便于对照）
3. `清洗日志.md`（改了什么、多少行受影响）
4. 透视表与图表建议

## 输出原则

- **清洗前先备份**：原文件不覆盖，输出到新文件
- **每步可追溯**：清洗日志要写清"第 X 列做了什么操作，影响 Y 行"
- **不发明数据**：缺失就是缺失，不均值填充、不插值（除非用户明确要求）
- **结论基于数据**：写"3 月销售额环比下降 12%"，不写"销售情况不太乐观"
- **异常值不擅自删除**：标记出来，让用户判断是错误还是真实极值

## 红线

- 不篡改原始数据、不伪造统计结果
- 涉及个人信息（姓名、手机号、身份证）时，提醒用户脱敏后再分析
- 不提供财务、税务、法律的结论性建议（数据整理可以，专业判断请找专业人士）

## 付费模式（支付宝 AI 按量付费 · A2M 协议）

本 Skill 为**按调用量计费**的付费技能，单次调用价格 **¥0.01**。
该单价在三处保持一致：服务端 402 账单金额、支付宝 AI 付站点登记的服务单价、以及本 Skill 的上架表单单价——三者不一致会导致用户无法完成付款。

**四步编排（Agent 侧）**

| 步骤 | 动作 | 期望结果 |
|------|------|----------|
| `probe` | 发起调用，未携带支付凭证 | 收到 `402` + `Payment-Needed`（内含账单） |
| `pay` | 把账单交给支付宝官方支付能力拉起收银 | **由用户本人完成付款**，付款后取得 `Payment-Proof` |
| `complete` | 携带 `Payment-Proof` 重试同一请求 | 服务端验付通过后交付，返回 `200` + `Payment-Validation` |
| `ack` | 交付完成后回执履约确认 | 幂等处理，同一凭证重复请求不会重复扣费 |

**前置检查**：调用前先确认运行环境具备支付宝支付能力；不具备时应明确提示用户先安装官方「支付宝 AI 付」能力，而不是让调用静默失败，更不允许退化成免费旁路。

**异常处理**

| 情况 | 状态码 | 处置 |
|------|--------|------|
| 输入非法（如文件不存在、非表格文件） | `400` | 必须在发出账单**之前**拦截，不因非法输入收费 |
| 收款渠道未配置 | `503` | 明确拒绝，**不得免费放行** |
| 未携带凭证 / 验付失败 / 金额不符 | `402` | 回落并重新签发账单 |
| 验付网关不可达（结果不明） | `502` + `retry_with_same_proof=true` | **不得回落 402**，否则会诱导用户重复付款 |
| 履约确认失败 | `502` | 保留交付物，允许同一凭证重试，不重造交付物 |
| 用户取消付款 | — | 终止本次调用，不产生交付 |

**安全红线**

- 不暴露付款链接、二维码、交易号等敏感信息。
- 用户数据只在本地处理，**不上传任何数据到外部服务**。
- 私钥与商户配置只保存于服务端；**本 Skill 包内不含任何密钥、支付账号或收款码**。
- 免费内容仅限结构说明与元信息，不存在绕过计费的免费旁路。

**履约内容**：单次付费对应一次完整交付（四步工作流 + 四件交付物），并完成 `ack` 回执。

- Python 3.9+

- `pandas`（可选，缺失时脚本自动降级为纯标准库模式，处理速度慢但可用）
