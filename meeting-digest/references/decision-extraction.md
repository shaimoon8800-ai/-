# 决议识别与拍板判定

## 什么才算「决议」

**决议 = 明确的结论 + 有人拍板 + 有约束力**

三个条件缺一不可：

| 条件 | 判断信号 |
|---|---|
| 明确结论 | "就按方案 B 做" / "定下来用这个供应商" |
| 有人拍板 | 决策权人明确表态："可以""同意""就这么定" |
| 有约束力 | 后续行动以此为准，不再讨论 |

## 容易误判为决议的四种情况

### ❌ 情况 1：讨论激烈但没结论
```
A：我觉得方案 A 好　B：但方案 B 成本低　A：也是……
```
→ 这是**未决**，不是决议。

### ❌ 情况 2：有结论但没人拍板
```
A：那我们就用方案 A 吧？（没人回应，话题转走）
```
→ 这是**倾向**，不是决议。纪要里标为"未决（待 X 确认）"。

### ❌ 情况 3：主持人总结 ≠ 拍板
主持人说"大家的意见我总结一下：倾向于 A" → 这是**归纳**，不是决议。除非他说"那就定 A"。

### ❌ 情况 4：条件性结论
```
"如果测试数据没问题，就用 A"
```
→ 这是**有条件的决议**，要写清楚条件与条件未满足时的备选。

## 拍板人识别

按优先级判断：
1. 明确表态"可以/同意/就这么定"的人
2. 说"我来拍这个板""我负责"的人
3. 职级/角色上有决策权的人（主持人、项目 owner、需求方）
4. 全部缺失 → 标注「拍板人：待确认」

**不要默认主持人就是拍板人。**

## 决议强度分级

| 级别 | 表述 | 纪要写法 |
|---|---|---|
| 已定 | "定了""就这么办" | ✅ 决议 |
| 强倾向 | "我倾向于 A，大家没意见就 A" | ⚠️ 弱决议（标注"默示通过"） |
| 弱倾向 | "我觉得 A 可能更好" | ❓ 未决 |
| 待定 | "再看数据""下次再议" | ❓ 未决 |

## 决议的输出要求

每条决议必须带：

```
| # | 决议内容 | 拍板人 | 依据 |
| 1 | 采用方案 B，下周三前启动 | 张总 | 成本测算表（段 18） |
```

**依据列**要写清是根据什么数据/讨论得出的，方便日后复盘"当时为什么这么定"。

## 决议的常见表述陷阱

| 原始表述 | 陷阱 | 正确处理 |
|---|---|---|
| "原则上同意" | 是同意还是不同意？ | 追问条件，标"附条件同意" |
| "先这样吧" | 临时还是定案？ | 标注"暂定，X 日前可调整" |
| "我不管了，你们定" | 放弃决策权 | 拍板人写实际拍板者 |
| "可以试试" | 试验性授权 | 标"试运行，需 X 后复评" |
