# 风险与异议标记

## 为什么要单独记录

会议纪要只记"定了什么"是不够的——**当时没人听的反对意见，往往就是后来的事故原因**。记录风险与异议，是给未来的自己留证据。

## 三类需要标记的信息

### 1. 风险（Risk）
对未来的负面预判。
识别信号：`风险` `隐患` `可能出问题` `万一` `如果…就会` `担心`

### 2. 异议（Objection）
明确的不同意见。
识别信号：`我不同意` `但是` `我觉得这样不行` `有个问题` `不太行`

### 3. 前提条件（Precondition）
决议生效的隐含依赖。
识别信号：`前提是` `必须先` `得先解决` `如果 A 没问题的话`

## 标记格式

```markdown
## 四、风险与异议

**⚠️ 风险**
- [风险内容] —— 提出人：X —— 影响面：高/中/低
  - 应对建议：（会议中提出的，或标记"未讨论"）

**❓ 异议（未被采纳）**
- [异议内容] —— 提出人：X —— 当前状态：已被否决 / 待复议

**🔗 前提条件**
- [决议 N] 生效前提：[条件] —— 若条件不成立，需回退到：[备选方案]
```

## 关键要求

### 必须标注"是否被采纳"
```
A：我担心成本会超
B：算过了，在预算内
→ 记录：A 提出成本风险，B 以测算数据回应（未形成阻塞）
```

**未被采纳的异议要特别标出**——这是后续追责/复盘的唯一线索。

### 必须标注提出人
"有人担心" ≈ 没记。**谁说的必须写清楚**。

### 不评价对错
纪要不做判断。写"X 提出 Y 风险"，不写"X 提出的风险没有道理"。

## 风险等级参考

| 等级 | 判断依据 |
|---|---|
| 高 | 可能影响项目成败 / 有法务合规风险 / 涉及大额成本 |
| 中 | 可能延期 / 影响部分功能 / 需要额外投入 |
| 低 | 有替代方案 / 影响可控 |

等级**由会议中提出的判断为准**，会议没说就标"未评级"。

## 敏感议题处理

涉及以下内容时，输出前必须先提醒用户：

| 类型 | 提醒内容 |
|---|---|
| 人事（裁员、调岗、绩效） | 确认纪要知悉范围，避免扩散 |
| 薪酬与股权 | 建议脱敏后再分发 |
| 诉讼、纠纷、监管沟通 | 建议标注"内部资料，注意保密义务" |
| 客户隐私数据 | 建议脱敏（姓名、电话、身份证号） |
