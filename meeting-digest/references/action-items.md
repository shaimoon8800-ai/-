# 待办提取与责任人归属

## 什么才算「待办」

**待办 = 动作 + 可验收的交付物**

| 原始说法 | 是不是待办 | 原因 |
|---|---|---|
| "这个我们跟进一下" | ❌ | 没有交付物、没有责任人 |
| "李四，你周四前给一版方案" | ✅ | 有责任人、有交付物、有时间 |
| "需要再看看数据" | ❌ | 谁看？看什么数据？什么时候？ |
| "我这边周五之前把接口对完" | ✅ | 有承诺、有交付物、有时间 |
| "大家想想还有什么风险" | ❌ | 无法验收 |

**处理原则**：不合格的"待办" → 要么**补全**（从上下文推断责任人与时间，并标注推断依据），要么**降级**为"未决事项"。

## 四要素提取

| 要素 | 提取来源 | 缺失时 |
|---|---|---|
| **事项** | 动词 + 对象 + 交付物 | 必填，否则不是待办 |
| **负责人** | 明确点名 / 主动认领 / 按职责推断 | 写「待确认」 |
| **截止时间** | 明确日期 / 相对时间（"下周三"）→ 换算成绝对日期 | 写「待确认」 |
| **依赖/备注** | 前置条件、需要谁配合 | 可空 |

### 相对时间换算（必须换算）

| 说法 | 换算规则 |
|---|---|
| 明天 | 会议日期 +1 天 |
| 后天 | +2 天 |
| 下周 | 下周一（若会议在周三之后） |
| 下周三 | 会议所在周的下一个周三 |
| 月底前 | 当月最后一天 |
| 尽快 | 标注「ASAP（无明确日期）」 |
| 这个季度 | 换算成季度末日期并标注 |

**不明会议日期时，向用户确认，不要自己假设。**

## 责任人归属的三个陷阱

### 陷阱 1：多人在场时误判
```
"这个我们市场部来搞" → 责任人是"市场部"，不是具体的谁
```
处理：写「市场部（具体执行人待确认）」。

### 陷阱 2：被动语态
```
"这个应该要做一下" → 没有主语
```
处理：回溯上文找"谁最关心这件事"，标注为推断并写明依据；找不到就写「待确认」。

### 陷阱 3：口头应承
```
A：谁来弄？　B：嗯……（含糊） → B 未明确认领
```
处理：**不算认领**，写「待确认」。

## 输出格式

```markdown
| # | 事项 | 负责人 | 截止时间 | 依赖/备注 |
|---|---|---|---|---|
| 1 | 输出方案 B 的详细成本测算 | 张三 | 2026-10-17 | 需财务提供上季度数据 |
| 2 | 与供应商 A 确认报价 | 待确认 | 2026-10-20 | 议题 2 遗留 |
```

## 优先级排序（可选）

若会议中明确了优先级，按此排序并在表中加一列：

| 级别 | 判断依据 |
|---|---|
| P0 | 明确说"最重要""必须这周完成" |
| P1 | 有明确截止时间 |
| P2 | 无时间要求的一般事项 |

## 待办清单的落地建议

交付时附一段给用户的操作建议：

- 待办最好**当场同步到任务系统**（飞书/钉钉/Notion/Jira），纪要本身会沉底
- 每条待办应该是**一个人 + 一个交付物 + 一个日期**
- 「待确认」项要当场追问，隔天后追起来成本翻倍

## 自检

- [ ] 每条待办都能验收吗？（能判断"做完了没有"）
- [ ] 相对时间都换算成绝对日期了吗？
- [ ] 有没有把含糊应承当成认领？
- [ ] 责任人是不是具体的人，而不是部门？
