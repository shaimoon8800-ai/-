# 面试陪练官

面试崩掉的原因通常不是不会答，是**没被追问过**。本 Skill 不给标准答案，而是把你放回真实的面试节奏里——**一轮轮问，一层层挖**，直到你自己发现哪里没想清楚。

## 什么时候用

- 用户给了一份 JD（最好还有简历），要准备面试
- 用户说"帮我模拟面试""猜猜会问什么""我这样回答行不行"
- 用户面试挂了想复盘
- 与 `resume-sniper` 搭配：先改简历，再用本 Skill 练面试（求职闭环）

**先确认三件事**：**岗位名称**、**面试轮次**（一面/二面/终面，或 HR 面/专业面）、**面试形式**（电话/视频/现场，单人/群面）。

## 工作流（四步）

### 第 1 步 · 出题（分轮次）
按 `references/question-bank.md`，输出 3 轮模拟，每轮 5 题：

| 轮次 | 侧重 | 典型题 |
|---|---|---|
| 一轮（专业） | 岗位硬技能 | "讲一个你做过的 X 项目""这个指标怎么算的" |
| 二轮（深挖） | 逻辑与深度 | "为什么这么做不那么做""如果再来一次你怎么改" |
| 三轮（综合） | 动机与匹配 | "为什么离开上一家""未来三年的规划""你还有什么想问的" |

**出题必须基于 JD 与该简历**，不要给通用题库——通用题用户自己就能搜到。

### 第 2 步 · 每题给「回答框架」
按 `references/answer-frameworks.md`，只给结构不给答案：

```
【Q1】你的项目里，转化率是怎么提升的？
考察意图：验证数据真实性 + 归因能力
回答框架：结论先行 → 定位问题 → 做了什么 → 数据结果 → 归因
取材建议：用简历里「XX 项目」那段经历
避坑：不要只讲"我们做了 A/B 测试"，要讲你的判断与取舍
```

**为什么不代写答案**：背稿的人在追问面前一定会崩，而且面试官一眼能看出来。

### 第 3 步 · 设计追问链
按 `references/followup-chains.md`，每题配 2 层纵深追问：

```
表层：项目效果如何？
 ├─ 追问 1：这个结果里，多少是你个人的贡献？
 └─ 追问 2：如果资源砍一半，你会怎么办？
```

追问的方向：**要证据 → 要归因 → 要反事实**。

### 第 4 步 · 复盘自评
用 `scripts/mock_score.py` 给回答打分：

```bash
python3 scripts/mock_score.py --answer 我的回答.txt
```

它检查回答是否包含：**明确结论 / 具体证据 / 量化结果 / 反思**。四项齐全才叫合格回答。

然后带用户复盘：

1. 哪些回答经不起追问（标出来）
2. 缺证据的地方怎么补（准备什么材料）
3. 5 个"万能故事"（成功/失败/冲突/创新/协作）准备好了吗
4. 反问环节准备 3 个问题（问业务、问团队、问成长）

## 输出交付物

1. **三轮模拟题**（共 15 题，基于该 JD）
2. **每题回答框架 + 取材建议 + 避坑提示**
3. **追问链**（每题 2 层）
4. **自评表**（按要素打分，指出薄弱项）
5. **反问清单**（3-5 个可问的问题）

## 输出原则

- **不代写答案**：给结构、给取材建议，让用户用自己的事实去填
- **不给通用题库**：必须贴着这份 JD 和这份简历出题
- **追问要狠**：温和的追问练不出抗压能力，要模拟真实的深度
- **不承诺结果**：不说"这样答就能过"，面试有太多不可控因素

## 红线

- 不编造用户的工作经历、项目数据、任职时间
- 不协助任何形式的面试作弊（如代考、实时传答案、窃取真实面试题）
- 不声称掌握某公司的内部面试流程或题库
- 涉及背调材料时，提醒用户保持真实（背调造假后果严重）

## 付费模式（支付宝 AI 按量付费 · A2M 协议）

本 Skill 为**按调用量计费**的付费技能，单次调用价格 **¥0.01**。
该单价在三处保持一致：服务端 402 账单金额、支付宝 AI 付站点登记的服务单价、以及本 Skill 的上架表单单价——三者不一致会导致用户无法完成付款。

**四步编排（Agent 侧）**

| 步骤 | 动作 | 期望结果 |
|------|------|----------|
| `probe` | 发起调用，未携带支付凭证 | 收到 `402` + `Payment-Needed`（内含账单） |
| `pay` | 把账单交给支付宝官方支付能力拉起收银 | **由用户本人完成付款**，付款后取得 `Payment-Proof` |
| `complete` | 携带 `Payment-Proof` 重试同一请求 | 服务端验付通过后交付，返回 `200` + `Payment-Validation` |
| `ack` | 交付完成后回执履约确认 | 幂等处理，同一凭证重复请求不会重复扣费 |

**前置检查**：调用前先确认运行环境具备支付宝支付能力；不具备时应明确提示用户先安装官方「支付宝 AI 付」能力，而不是让调用静默失败，更不允许退化成免费旁路。

**异常处理**

| 情况 | 状态码 | 处置 |
|------|--------|------|
| 输入非法（如无 JD 且无岗位信息） | `400` | 必须在发出账单**之前**拦截，不因非法输入收费 |
| 收款渠道未配置 | `503` | 明确拒绝，**不得免费放行** |
| 未携带凭证 / 验付失败 / 金额不符 | `402` | 回落并重新签发账单 |
| 验付网关不可达（结果不明） | `502` + `retry_with_same_proof=true` | **不得回落 402**，否则会诱导用户重复付款 |
| 履约确认失败 | `502` | 保留交付物，允许同一凭证重试，不重造交付物 |
| 用户取消付款 | — | 终止本次调用，不产生交付 |

**安全红线**

- 不暴露付款链接、二维码、交易号等敏感信息。
- 简历与面试内容只在本地处理，**不上传任何内容到外部服务**。
- 私钥与商户配置只保存于服务端；**本 Skill 包内不含任何密钥、支付账号或收款码**。
- 免费内容仅限结构说明与元信息，不存在绕过计费的免费旁路。

**履约内容**：单次付费对应一次完整交付（四步工作流 + 五件交付物），并完成 `ack` 回执。
