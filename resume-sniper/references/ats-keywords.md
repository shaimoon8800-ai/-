# ATS 过筛机制与中文简历规范

## ATS 是什么，为什么关键

ATS（Applicant Tracking System）是招聘系统的自动筛选层。大厂、外企、互联网公司基本都在用（如 Moka、北森、Workday、SuccessFactors）。

它的行为逻辑：

1. **解析**：把 PDF/Word 简历拆成结构化字段（姓名、公司、职位、时间、技能）
2. **打分**：与 JD 关键词做加权匹配
3. **排序**：低分简历在 HR 打开之前就被折叠

**结论：格式不规范 → 解析失败 → 内容再好也是 0 分。**

## 格式规范（决定能不能被解析）

| 项 | 正确做法 | 会导致解析失败的写法 |
|---|---|---|
| 文件格式 | PDF（首选）或 Word | 图片型 PDF、扫描件 |
| 版面 | 单栏 | 双栏、三栏、左右图文混排 |
| 字体 | 系统标准字体 | 艺术字、手写体 |
| 标题 | 用标准词：工作经历 / 教育背景 / 项目经历 | "我的旅程""成长足迹" |
| 表格 | 尽量避免，必要时光框线 | 复杂合并单元格 |
| 页眉页脚 | 不放关键信息 | 把电话/邮箱放在页眉里 |
| 图形 | 不放 | 技能条、雷达图、进度条（无法解析） |
| 照片 | 国内简历可放，右上角 | 全页背景图 |

## 关键词匹配的三个层级

1. **完全匹配**：JD 写 `SQL`，简历写 `SQL` → 满分
2. **同义匹配**：JD 写 `数据分析`，简历写 `数据挖掘` → 部分分（取决于系统词库）
3. **不匹配**：JD 写 `Python`，简历写 `编程能力` → 0 分

**所以：JD 里出现的专业名词，原词照抄进简历。**

## 中文简历特有规范

### 必含字段
姓名 · 联系方式（手机 + 邮箱）· 求职意向（岗位名要与 JD 一致）· 教育背景（学校/专业/学历/起止时间）· 工作经历（公司/职位/起止时间/职责成果）

### 加分字段
- 作品集/项目链接（放在姓名旁）
- 证书与语言能力
- 现居城市（异地求职时重要，涉及录用成本）

### 常见减分项
- 简历命名混乱：应为 `姓名-应聘岗位-工作年限.pdf`
- 求职意向写了三个不相关岗位
- 期望薪资写死一个数字（除非 HR 要求）
- 婚姻/生育状况（除非岗位明确要求）
- 大段自我评价（占 1/4 页那种）

## 篇幅控制

| 工作年限 | 建议页数 |
|---|---|
| 应届 / 1 年内 | 1 页 |
| 2-5 年 | 1-2 页 |
| 5-10 年 | 2 页 |
| 10 年以上 | 2-3 页（可加管理履历摘要） |

## 交付前自检清单

- [ ] 目标岗位名称与 JD 完全一致
- [ ] JD 的 5 个核心关键词原词出现在简历里
- [ ] 每条经历以动词开头
- [ ] 至少 60% 的经历带量化结果
- [ ] 时间线连续，断档有说明
- [ ] 无拼写、无错别字、无繁体简体混用
- [ ] 文件名规范：`姓名-岗位-年限.pdf`
- [ ] 导出 PDF 后确认文字可选中（不是图片）
