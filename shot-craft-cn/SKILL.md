# 短视频分镜工厂

短视频难的不是拍，是**开拍前那半小时**——对着空白的备忘录想不出钩子。本 Skill 把"一个主题"变成"一张能照着拍的分镜表"。

## 什么时候用

- 用户给了一个主题、产品、卖点或一段口播要点，要做成短视频
- 用户说"没灵感""不知道拍什么""帮我写个脚本"
- 用户要写带货口播、知识分享、探店、剧情类短视频
- 用户已有稿子，要拆成分镜

**信息不足时**（只说"帮我做个视频"）：先问清三件事——**平台**（抖音/视频号/小红书）、**时长**（15s/60s/3min）、**目标**（涨粉/带货/引流私域）。这三个决定了节奏和结构。

## 工作流（五步）

### 第 1 步 · 定角度
按 `references/script-structure.md`，先给 **3 个选题角度**，每个注明：

- 角度名（如「反常识」「痛点直击」「对比测评」）
- 目标受众
- 核心信息（一句话）
- 预估时长

**让用户挑一个**，或明确说"我按第 X 个往下做"。不要一次生成三套完整分镜。

### 第 2 步 · 写钩子
按 `references/hook-formulas.md` 给 **5 版 3 秒钩子**：

| 流派 | 示例结构 |
|---|---|
| 悬念式 | "我用了三年才发现，XX 一直是错的" |
| 痛点式 | "是不是每次 XX 都让你想砸电脑" |
| 数字式 | "三招，让 XX 效率翻倍" |
| 反常识 | "别再 XX 了，这才是正确做法" |
| 身份呼唤 | "做 XX 的人，这条你必须看" |

### 第 3 步 · 拆分镜
按 `references/shot-list-format.md` 输出标准分镜表：

| 镜号 | 时长 | 画面/景别 | 台词/字幕 | 拍法 | 道具/备注 |
|---|---|---|---|---|---|
| 1 | 0-3s | 特写，人物入画 | "钩子台词" | 手持，快速推近 | 无 |
| 2 | 3-8s | 中景 | 正文第一段 | 固定机位 | 桌面道具 |

**台词必须口语化**：写出来要能一口气念完，拗口的自动改短。

### 第 4 步 · 时长校验
运行 `scripts/shot_duration.py`：

```bash
python3 scripts/shot_duration.py --minutes 1.5 --script 分镜表.txt
```

它会按中文口播 ≈ 240 字/分钟估算时长，检查是否超出平台上限。**超了就必须删内容，不能硬塞**。

### 第 5 步 · 交付五件套

1. **选题角度**（3 选 1 已定）
2. **钩子**（5 版）
3. **分镜表**（可直接拍）
4. **拍摄清单**（道具、场地、机位、服装）
5. **发布文案 + 标题 3 版**（按平台规则）

## 平台节奏规则

| 平台 | 黄金时长 | 钩子窗口 | 节奏特点 |
|---|---|---|---|
| 抖音 | 21-45s | 前 3 秒 | 快切，每 3-5 秒一个信息点 |
| 视频号 | 60-90s | 前 5 秒 | 稍慢，重情绪与观点 |
| 小红书 | 30-60s | 前 3 秒 | 真实感，少喊麦，重画面质感 |
| B 站 | 3-8min | 前 15 秒 | 可长，重信息密度 |

## 输出原则

- **可拍优先**：分镜要写到"谁、在哪、拿什么、怎么拍"，不是抽象描述
- **台词口语化**：写完自己念一遍，拗口的必须改
- **不写做不到的镜头**：用户是手机拍还是团队拍，镜头设计要匹配（除非用户明确说有大制作）
- **钩子不骗人**：悬念可以有，但不能挂羊头卖狗肉（点进来发现不是那么回事，完播率会崩）

## 红线

- 不做虚假宣传、不编造产品功效
- 不设计诱导性、欺骗性内容（如假抽奖、假限量）
- 涉及医疗、金融、教育等特殊行业，提醒用户遵守行业广告规范
- 不协助抄袭他人爆款脚本的原创性表达

## 付费模式（支付宝 AI 按量付费 · A2M 协议）

本 Skill 为**按调用量计费**的付费技能，单次调用价格 **¥0.01**。
该单价在三处保持一致：服务端 402 账单金额、支付宝 AI 付站点登记的服务单价、以及本 Skill 的上架表单单价——三者不一致会导致用户无法完成付款。

**四步编排（Agent 侧）**

| 步骤 | 动作 | 期望结果 |
|------|------|----------|
| `probe` | 发起调用，未携带支付凭证 | 收到 `402` + `Payment-Needed`（内含账单） |
| `pay` | 把账单交给支付宝官方支付能力拉起收银 | **由用户本人完成付款**，付款后取得 `Payment-Proof` |
| `complete` | 携带 `Payment-Proof` 重试同一请求 | 服务端验付通过后交付，返回 `200` + `Payment-Validation` |
| `ack` | 交付完成后回执履约确认 | 幂等处理，同一凭证重复请求不会重复扣费 |

**前置检查**：调用前先确认运行环境具备支付宝支付能力；不具备时应明确提示用户先安装官方「支付宝 AI 付」能力，而不是让调用静默失败，更不允许退化成免费旁路。

**异常处理**

| 情况 | 状态码 | 处置 |
|------|--------|------|
| 输入非法（如无主题、未指定平台） | `400` | 必须在发出账单**之前**拦截，不因非法输入收费 |
| 收款渠道未配置 | `503` | 明确拒绝，**不得免费放行** |
| 未携带凭证 / 验付失败 / 金额不符 | `402` | 回落并重新签发账单 |
| 验付网关不可达（结果不明） | `502` + `retry_with_same_proof=true` | **不得回落 402**，否则会诱导用户重复付款 |
| 履约确认失败 | `502` | 保留交付物，允许同一凭证重试，不重造交付物 |
| 用户取消付款 | — | 终止本次调用，不产生交付 |

**安全红线**

- 不暴露付款链接、二维码、交易号等敏感信息。
- 私钥与商户配置只保存于服务端；**本 Skill 包内不含任何密钥、支付账号或收款码**。
- 免费内容仅限结构说明与元信息，不存在绕过计费的免费旁路。

**履约内容**：单次付费对应一次完整交付（五步工作流 + 五件套输出），并完成 `ack` 回执。
