# JD 五层拆解规则

## 为什么要拆
JD 是人写的，写的人未必诚实也未必专业。同一句话在不同层级含义完全不同：
"熟悉 Python"（硬性）和"有 Python 经验者优先"（加分）是两种命运。

## 第一层：硬性要求（命中才有面试机会）

识别信号：
- "必须""要求""具备…资格"
- 学历：`本科及以上` `硕士` `985/211`
- 年限：`3 年以上` `5 年经验`
- 证书：`CPA` `PMP` `教师资格证` `职称`
- 必备工具：`精通 Excel` `熟悉 Kubernetes`

处理：逐条对照用户实际情况，任何一条不满足 → 在交付物的「缺口清单」里标红，并给出判断（够不够得着 / 建议放弃 / 有无替代）。

## 第二层：加分项（决定内容排序）

识别信号：`优先` `加分` `者佳` `有…更好` `熟悉…者优先`

处理：把简历中命中加分项的内容**上移、展开**；未命中的**不硬凑**。

## 第三层：显性关键词（必须原词出现）

JD 原文里的名词性词汇，尤其是：
- 技术栈：`Java` `React` `SQL` `Flink`
- 工具：`Jira` `Figma` `Tableau` `SAP`
- 方法论：`敏捷开发` `OKR` `A/B 测试` `六西格玛`
- 业务词：`私域` `GMV` `转化率` `复购`

处理：**这些词要在简历里原样出现**。ATS 做的是字符串匹配，"用户增长"和"用户拉新"在机器眼里不是一个词。

## 第四层：隐性关键词（提升人味）

JD 用了 A 说法，简历行业习惯用 B 说法时，**两个都写**：

| JD 说法 | 简历常见说法 |
|---|---|
| 用户增长 | 拉新、留存、裂变 |
| 降本增效 | 成本优化、流程精简 |
| 数据驱动 | 数据分析、指标体系 |
| 从 0 到 1 | 新业务搭建、项目立项 |
| 商业化 | 变现、营收 |

## 第五层：淘汰线（提前预警）

**"看起来不像要求"的硬条件**，命中即大概率被系统或 HR 直接筛掉：

- 学历门槛（尤其是"全日制""统招"字样）
- 行业经验要求（"必须有金融行业经验"）
- 地域/到岗要求（"需驻场""接受出差 50%"）
- 年龄暗示（"年轻有活力""35 岁以下"）
- 时间空窗期过长的隐性追问

处理：不替用户隐瞒，但要在交付物里**明确提示**，让用户自己决策。若命中淘汰线，如实说"这条路成功率低"，不要给虚假安慰。

## 输出模板

```
## 一、硬性要求（逐条核对）
1. [要求] → 用户情况 → ✅/❌/⚠️

## 二、加分项
...

## 三、显性关键词（必须原词命中）
[词1] [词2] ...

## 四、隐性关键词（同义替换机会）
[JD 说法] ≈ [简历说法]

## 五、淘汰线与风险提示
...
```
