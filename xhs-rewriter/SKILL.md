# 小红书爆款改写器

小红书不是"短一点的公众号"。同一个内容，在这里要**像个人在说话**——有情绪、有细节、有具体到离谱的体验。本 Skill 把素材改成这个语感。

## 什么时候用

- 用户给了一段素材（长文、产品简介、公众号文案、口播稿），要做成小红书笔记
- 用户说"帮我写个小红书""这个怎么发小红书""标题怎么写"
- 用户要一稿多平台，需要小红书版本
- 用户要优化已有笔记的标题或标签

**先确认三件事**：**赛道**（美妆/穿搭/母婴/职场/家居…）、**目标**（涨粉/引流/带货/品牌）、**身份**（素人分享 / 专业博主 / 品牌号）。这三个决定了语气。

## 工作流（五步）

### 第 1 步 · 素材拆解
从原始素材里抽出：

- 核心卖点 / 核心信息（1 个，不是 5 个）
- 可具象化的细节（数字、场景、对比、感受）
- 目标读者的具体处境（"加班到十点还想做顿饭的人"）

### 第 2 步 · 标题 5 版
按 `references/title-formulas.md` 给 5 版，覆盖不同流派：

| 流派 | 结构 |
|---|---|
| 数字清单 | "3 个方法，让我 XX 从 A 到 B" |
| 身份共鸣 | "打工人真的可以试试这个" |
| 反常识 | "别再 XX 了，我踩过坑" |
| 结果对比 | "坚持 30 天，我的 XX 变了" |
| 悬念留白 | "同事问我最近怎么不一样了" |

⚠️ **标题硬约束：≤20 字**（含标点）。用 `scripts/xhs_check.py` 校验，超了必须改。

### 第 3 步 · 正文结构
按 `references/note-structure.md`，采用以下四段式：

```
【钩子】前 2 行必须让人想点"展开"（前两行是唯一被展示的）
【铺垫】我的情况 / 为什么关注这个（建立可信度）
【干货】分点讲清（3-5 点，每点带具体细节或数字）
【互动】提问 / 求推荐 / 征集经验（引导评论）
```

**语感要求**：
- 短句为主，一句一个意思
- 允许口语（"真的""巨""谁懂啊"），但不堆砌
- 用具体名词替代形容词（"用了 3 个月" 优于 "用很久了"）
- emoji 每段 0-2 个，用于分段而非装饰

### 第 4 步 · 标签与配图
- **标签**：1 个大词（#职场）+ 2-3 个精准词（#写简历）+ 1-2 个长尾词（#应届生求职）
- **配图建议**：首图（决定点击率）、内容图（承载信息）、场景图（真实感），并说明每张画什么

### 第 5 步 · 校验
运行 `scripts/xhs_check.py`：

```bash
python3 scripts/xhs_check.py --text 笔记.txt
```

检查项：标题字数、正文总字数、标签数量、违禁词、导流类表述。

## 输出交付物

1. **标题 5 版**（全部 ≤20 字，标注流派）
2. **正文全文**（可直接复制发布）
3. **标签组合**（含大词/精准词/长尾词说明）
4. **配图建议**（首图 + 内容图 + 场景图，各写清画面）
5. **发布建议**（时段、互动引导话术、评论区预备问题）

## 平台禁忌（必须主动检查）

| 类型 | 禁止表述 | 说明 |
|---|---|---|
| 导流 | 留联系方式、引导离开平台、暗示私下联系 | 平台会限流 |
| 绝对化 | "最有效""第一""永久""彻底根治" | 广告法风险 |
| 医疗功效 | "治疗""消炎""祛疾" | 非医疗账号高危 |
| 虚假承诺 | "3 天瘦 10 斤""一周涨粉 1 万" | 违规且不可信 |
| 抄袭 | 搬运他人笔记原文 | 侵权 |
| 诱导互动 | "点赞过百就…"类型的硬性诱导 | 平台判定违规 |

## 输出原则

- **像一个真人**：不写"我们的产品具有以下优势"这种说明书口气
- **细节换信任**：具体的时间、价格、场景、感受，比形容词有用
- **不编造体验**：用户没提供的效果、数据、对比，不能替用户编
- **一稿一平台**：同一个素材给不同平台时，输出各自版本并标注差异逻辑

## 红线

- 不编造使用体验、效果数据、他人评价
- 不写虚假种草（未使用却写成亲身体验）
- 医疗、金融、教育等特殊行业，提示用户遵守行业广告规范
- 不协助抄袭他人原创内容

## 付费模式（支付宝 AI 按量付费 · A2M 协议）

本 Skill 为**按调用量计费**的付费技能，单次调用价格 **¥0.01**。
该单价在三处保持一致：服务端 402 账单金额、支付宝 AI 付站点登记的服务单价、以及本 Skill 的上架表单单价——三者不一致会导致用户无法完成付款。

**四步编排（Agent 侧）**

| 步骤 | 动作 | 期望结果 |
|------|------|----------|
| `probe` | 发起调用，未携带支付凭证 | 收到 `402` + `Payment-Needed`（内含账单） |
| `pay` | 把账单交给支付宝官方支付能力拉起收银 | **由用户本人完成付款**，付款后取得 `Payment-Proof` |
| `complete` | 携带 `Payment-Proof` 重试同一请求 | 服务端验付通过后交付，返回 `200` + `Payment-Validation` |
| `ack` | 交付完成后回执履约确认 | 幂等处理，同一凭证重复请求不会重复扣费 |

**前置检查**：调用前先确认运行环境具备支付宝支付能力；不具备时应明确提示用户先安装官方「支付宝 AI 付」能力，而不是让调用静默失败，更不允许退化成免费旁路。

**异常处理**

| 情况 | 状态码 | 处置 |
|------|--------|------|
| 输入非法（如无素材、未指定赛道） | `400` | 必须在发出账单**之前**拦截，不因非法输入收费 |
| 收款渠道未配置 | `503` | 明确拒绝，**不得免费放行** |
| 未携带凭证 / 验付失败 / 金额不符 | `402` | 回落并重新签发账单 |
| 验付网关不可达（结果不明） | `502` + `retry_with_same_proof=true` | **不得回落 402**，否则会诱导用户重复付款 |
| 履约确认失败 | `502` | 保留交付物，允许同一凭证重试，不重造交付物 |
| 用户取消付款 | — | 终止本次调用，不产生交付 |

**安全红线**

- 不暴露付款链接、二维码、交易号等敏感信息。
- 私钥与商户配置只保存于服务端；**本 Skill 包内不含任何密钥、支付账号或收款码**。
- 免费内容仅限结构说明与元信息，不存在绕过计费的免费旁路。

**履约内容**：单次付费对应一次完整交付（五步工作流 + 五件交付物），并完成 `ack` 回执。
