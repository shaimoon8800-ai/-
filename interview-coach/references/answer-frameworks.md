# 回答框架库

> 本文件只给**结构**，不给答案。用户必须用自己的真实经历去填。

## STAR（最通用）

```
S 情境 Situation  —— 什么时候、什么背景（1 句）
T 任务 Task       —— 你的目标是什么（1 句）
A 行动 Action     —— 你具体做了什么（重点，2-3 句）
R 结果 Result     —— 带来了什么结果（要带数字）
```

**适用**：行为类问题（"讲一次你…的经历"）

**常见错误**：
- S 讲太久（背景铺垫 2 分钟，行动只有 10 秒）
- A 里说"我们"而不是"我"（面试官想知道你做了什么）
- R 没有数字

**时间分配**：S 10% / T 10% / A 60% / R 20%

## 金字塔（结论先行）

```
结论 —— 先给答案
论据 1 —— 支撑结论的第一个理由
论据 2 —— 第二个理由
论据 3 —— 第三个理由
总结 —— 回到结论
```

**适用**：观点类问题（"你怎么看 XX""你会怎么做"）

**关键**：第一句话就是答案。不要"先说一下背景"。

## 对比式

```
方案 A 的优点与代价
方案 B 的优点与代价
我的选择与理由
（如果有）当时的实际结果
```

**适用**：决策类问题（"为什么这么做不那么做"）

**加分点**：说出被否方案的问题在哪，证明你评估过。

## 归因式

```
结果是什么
直接原因是什么（可量化的）
根本原因是什么
我怎么发现的
```

**适用**：数据分析类、复盘类问题

**关键**：区分"直接原因"（表面）和"根本原因"（机制）。

## 反事实式

```
当时的情况
如果重做，我会改变什么
为什么这么改会更好
```

**适用**：被问"如果再来一次"时

**注意**：不要过度自我否定，要体现"学到了什么"。

## 边界式（讲贡献）

```
项目整体目标是…
我在其中负责…
我的具体产出是…
团队其他人的部分…
```

**适用**：被问"这个成果里你的贡献占多少"

**关键**：诚实区分个人与团队，同时把你的部分讲清楚。含糊其辞反而被怀疑。

## 应对"不会答"的问题

```
1. 承认边界：「这块我经验不多」
2. 给思路：「但我的理解是…（讲你的推理过程）」
3. 请教：「不知道这样理解对不对？」
```

**绝对不要**：
- 硬编一个故事（追问两层就崩）
- 沉默或"嗯…"很久
- 直接说"不知道"就结束

## 每题回答前的三个自问

```
1. 我的结论是什么？（一句话能不能说出来）
2. 我有什么证据？（数字、事实、对比）
3. 对方可能追问什么？（提前想好第二层）
```

## 回答长度的控制

| 情况 | 时长 |
|---|---|
| 常规行为题 | 60-90 秒 |
| 复杂的项目回顾 | 2-3 分钟 |
| 观点题 | 45-60 秒 |
| 追问 | 30-45 秒 |

**超过 3 分钟没人打断**，通常不是好事——说明面试官已经走神了。主动收尾："大致是这样，您想深入了解哪部分？"

## 万能的五个故事

准备 5 个能覆盖绝大多数行为题的经历：

| 类型 | 能回答的问题 |
|---|---|
| 成功案例 | 最有成就感的项目、最好的一次结果 |
| 失败案例 | 最大的挫折、失败的项目、被否的方案 |
| 冲突案例 | 和同事/上级/客户意见不一致 |
| 创新案例 | 做过的不一样的事、流程改进 |
| 协作案例 | 跨部门合作、带新人、支持他人 |

**每个故事准备两个版本**：1 分钟版与 3 分钟版。
