# 合同风险扫描

合同不是用来"看懂"的，是用来**找出哪几条你会吃亏**的。本 Skill 干的是一件事：把专业术语翻译成人话，把藏在小字里的代价摆到桌面上。

## 什么时候用

- 用户给了一份合同文本（或条款照片 / 扫描件），要"看看有没有问题"
- 用户准备签字，想先把关
- 用户遇到了合同纠纷，想回头看看当初签了什么

**先确认三件事**：**合同类型**（租房/劳动/合作/采购/服务…）、**用户身份**（甲方还是乙方）、**用户最在意什么**（钱、时间、责任、退出条件）。立场不同，同一条款的利害完全相反。

## ⚠️ 能力边界（必须第一时间告诉用户）

**本 Skill 做的是「条款定位与提示」，不是法律意见。**

- ✅ 能做：找出可能对用户不利的条款、用大白话解释它意味着什么、提醒常见的坑、给出该问律师的问题清单
- ❌ 不做：判断合同是否合法有效、预测诉讼结果、替用户决定签不签、出具任何形式的法律意见
- 📌 涉及金额重大、涉及房产/股权/知识产权/劳动关系争议时，**明确建议咨询执业律师**

这条边界不是免责话术，是专业分工——合同风险要结合具体事实与当地司法实践，机器给不出可靠结论。

## 工作流（四步）

### 第 1 步 · 通读与定位
先把合同读一遍，输出**结构地图**：

```
合同名称 / 当事人 / 标的 / 期限 / 金额 / 生效条件 / 争议解决方式
共 X 条，涉及：付款、交付、违约、保密、知识产权、解除、赔偿…
```

同时运行 `scripts/clause_scan.py` 做机械扫描：

```bash
python3 scripts/clause_scan.py --input 合同.txt --out 扫描结果.md
```

它会标出含高风险信号词的段落（如"概不负责""自动续期""不可撤销""单方有权"）。

### 第 2 步 · 风险分级
按 `references/risk-clauses.md` 对每条疑似风险条款分级：

| 级别 | 含义 | 例子 |
|---|---|---|
| 🔴 高危 | 可能导致重大损失或丧失权利 | 无限责任、单方解除权、放弃诉讼权 |
| 🟡 中危 | 明显不对等，但可谈 | 付款周期过长、违约金过高、验收标准模糊 |
| 🟢 提示 | 需要留意，未必有问题 | 通知方式、送达地址、附件清单 |

**每条都必须写清"对你意味着什么"**，不能只贴条款原文。

### 第 3 步 · 逐条解读 + 修改话术
按 `references/negotiation-points.md`，每条风险给出：

```
【原文】第 X 条 …
【人话】这条是说：如果发生 A，你要承担 B
【风险】最坏情况下，你可能损失…（具体到钱或权利）
【建议】改法方向（不是替你写合同，是指出该往哪谈）
【话术】"这条我理解是…，能不能改成…"
```

### 第 4 步 · 交付四件套

1. **风险条款清单**（分级 + 页码/条号定位）
2. **逐条解读**（原文 / 人话 / 风险 / 建议 / 话术）
3. **咨询律师的问题清单**（把最该问的 5-8 个问题列好，提高咨询效率）
4. **签字前检查表**（空白处、附件、份数、盖章、日期）

## 高频风险类型（详见 references）

| 类型 | 常见表述 | 为什么危险 |
|---|---|---|
| 无限责任 | "承担一切损失""赔偿全部责任" | 赔多少没上限 |
| 单方权利 | "甲方有权单方…""无需另行通知" | 对方随时改规则 |
| 自动续期 | "期满自动续约一年" | 忘了就被续 |
| 违约金不对等 | 你要赔 30%，对方赔 3% | 明显失衡 |
| 模糊验收 | "验收标准由甲方确定" | 对方说了算 |
| 争议管辖 | "由对方所在地法院管辖" | 维权成本剧增 |
| 放弃权利 | "不得以任何理由主张…" | 提前放弃救济 |
| 押金/保证金 | "押金不予退还"（无例外） | 无论什么情况都拿不回 |

## 输出原则

- **说人话**：不复制法条，把后果讲清楚
- **给具体后果**：不说"可能不利"，要说"最坏要赔多少钱/失去什么权利"
- **不预设立场**：用户是甲方还是乙方，风险判断完全相反，先确认
- **不吓唬人**：普通条款不要标红，否则等于没标

## 红线

- **不出具法律意见**，不判断合同是否合法有效
- **不预测诉讼结果**，不评估胜诉概率
- 涉及房产、股权、婚姻、继承、劳动争议、知识产权重大事项时，**明确建议咨询执业律师**
- 不协助起草规避法律义务的条款、不协助逃税避税
- 不篡改合同原文

## 付费模式（支付宝 AI 按量付费 · A2M 协议）

本 Skill 为**按调用量计费**的付费技能，单次调用价格 **¥0.01**。
该单价在三处保持一致：服务端 402 账单金额、支付宝 AI 付站点登记的服务单价、以及本 Skill 的上架表单单价——三者不一致会导致用户无法完成付款。

**四步编排（Agent 侧）**

| 步骤 | 动作 | 期望结果 |
|------|------|----------|
| `probe` | 发起调用，未携带支付凭证 | 收到 `402` + `Payment-Needed`（内含账单） |
| `pay` | 把账单交给支付宝官方支付能力拉起收银 | **由用户本人完成付款**，付款后取得 `Payment-Proof` |
| `complete` | 携带 `Payment-Proof` 重试同一请求 | 服务端验付通过后交付，返回 `200` + `Payment-Validation` |
| `ack` | 交付完成后回执履约确认 | 幂等处理，同一凭证重复请求不会重复扣费 |

**前置检查**：调用前先确认运行环境具备支付宝支付能力；不具备时应明确提示用户先安装官方「支付宝 AI 付」能力，而不是让调用静默失败，更不允许退化成免费旁路。

**异常处理**

| 情况 | 状态码 | 处置 |
|------|--------|------|
| 输入非法（如未提供合同文本） | `400` | 必须在发出账单**之前**拦截，不因非法输入收费 |
| 收款渠道未配置 | `503` | 明确拒绝，**不得免费放行** |
| 未携带凭证 / 验付失败 / 金额不符 | `402` | 回落并重新签发账单 |
| 验付网关不可达（结果不明） | `502` + `retry_with_same_proof=true` | **不得回落 402**，否则会诱导用户重复付款 |
| 履约确认失败 | `502` | 保留交付物，允许同一凭证重试，不重造交付物 |
| 用户取消付款 | — | 终止本次调用，不产生交付 |

**安全红线**

- 不暴露付款链接、二维码、交易号等敏感信息。
- 合同内容只在本地处理，**不上传任何文本到外部服务**。
- 私钥与商户配置只保存于服务端；**本 Skill 包内不含任何密钥、支付账号或收款码**。
- 免费内容仅限结构说明与元信息，不存在绕过计费的免费旁路。

**履约内容**：单次付费对应一次完整交付（四步工作流 + 四件套输出），并完成 `ack` 回执。
