# 经历改写：句式与动词表

## 核心句式

```
动词 + 对象 + 方法/工具 + 量化结果
```

反例 vs 正例：

| ❌ 原始 | ✅ 改写后 |
|---|---|
| 负责公司微信公众号运营 | 独立运营企业公众号，策划 12 期专题内容，3 个月内粉丝从 2k 增至 1.8w |
| 参与系统开发工作 | 主导订单模块重构，将接口平均响应时间从 800ms 降至 120ms |
| 协助领导完成销售任务 | 负责华东区 30 家客户维护，年度回款 420 万元，达成率 118% |
| 有一定的数据分析能力 | 用 SQL + Tableau 搭建销售看板，覆盖 6 个维度，被 3 个部门日常使用 |

## 动词表（按强度排序）

**主导类**（体现 ownership）
主导 · 牵头 · 独立负责 · 从 0 到 1 搭建 · 统筹 · 推动 · 落地

**优化类**（体现改进）
重构 · 优化 · 精简 · 提速 · 降低 · 标准化 · 自动化

**协作类**（体现配合）
协同 · 对接 · 联动 · 支撑 · 配合

**分析类**（体现思考）
拆解 · 复盘 · 归因 · 建模 · 测算 · 诊断

**避免使用**（弱化自己）
参与 · 协助 · 帮忙 · 了解 · 接触 · 学习（除非真的是学习阶段）

## 量化四来源

改写时优先找这四类数字，**全部必须来自用户提供的真实信息**：

1. **规模**：覆盖多少用户/客户/门店/区域，管理多少人
2. **幅度**：提升了 x%，降低了 y%，节省 z 小时/月
3. **金额**：营收、成本、预算、回款的绝对值
4. **周期**：多久完成，提前多少天

没有数字时，用占位符 `【请填：具体数值】`，**绝不自己发明**。

## STAR 压缩法

工作经历用 **STAR 压缩成 2-3 行**：
- S/T（背景与目标）：一句话，可省略
- A（动作）：动词开头的具体做法
- R（结果）：量化结果 + 业务影响

```
S/T：接手时该渠道月活持续下滑
A：重新划分用户分层，针对沉默用户设计召回策略，上线 3 组 A/B 测试
R：次月留存回升 14%，季度 GMV 增长 23%
```

## 排序原则

1. 与 JD 强相关的经历 → 上移、展开到 3-5 条要点
2. 弱相关但体量大的经历 → 保留但压缩到 1-2 条
3. 完全无关的经历 → 若占篇幅 > 20%，建议删除或一行带过
4. 时间倒序不可打破（HR 按时间线读）

## 常见改写误区

- **堆砌形容词**："高效""优秀""极强的"——删掉，换成事实
- **职责写成流程**："负责日常工作的执行与跟进"——等于没说，要写具体成果
- **堆技术名词**：把没用过的工具写进技能栏，面试第一个问题就崩
- **时间线断档不解释**：空窗超过 6 个月，建议主动加一行说明（进修/家庭/项目）
