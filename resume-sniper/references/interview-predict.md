# 面试问题预测逻辑

## 预测依据（四个来源）

1. **JD 的职责动词**：写"负责跨部门协调" → 必问"讲一次你协调多方冲突的经历"
2. **简历里的量化结果**：写了"提升 30%" → 必问"这 30% 怎么算出来的"
3. **简历里的薄弱点**：频繁跳槽、空窗期、职级倒挂、专业不对口
4. **岗位的通用高频题**：该职能的经典问题（见下方题库）

## 输出格式

每题必须带三项，缺一不可：

```
Q1. 【问题原文】
    考察意图：面试官想验证什么
    回答框架：用哪段经历 + 按什么结构讲（STAR / 金字塔 / 对比式）
```

**不代写答案**——写死了答案，用户背稿会在追问时崩。只给结构和取材建议。

## 通用高频题库（按职能）

### 通用（人人会被问）
1. 请做一下自我介绍（1 分钟版本 / 3 分钟版本）
2. 为什么离开上一家公司？
3. 为什么选择我们公司/这个岗位？
4. 你最大的缺点是什么？
5. 未来三年的职业规划？
6. 期望薪资多少？
7. 你还有什么问题想问我们？

### 技术/研发
- 讲一个你解决过最棘手的技术问题
- 项目中最难的技术决策是什么，为什么这么选
- 线上出过事故吗，怎么定位和复盘的

### 产品/运营
- 讲一个你从 0 到 1 的项目
- 这个数据为什么涨了，除了你说的原因还有别的可能吗
- 如果预算砍一半，你会怎么调整策略

### 销售/商务
- 讲一次你丢掉的大单，问题出在哪
- 怎么开拓一个完全陌生的客户
- 你手上有多少客户资源，怎么维护的

### 财务/法务
- 讲一次你发现的风险点
- 处理过最复杂的合规/税务问题
- 怎么在效率和合规之间取舍

### 管理岗追加
- 你怎么带一个能力一般的下属
- 团队和上级意见冲突时怎么办
- 讲一次你做的团队调整，结果如何

## 薄弱点的针对性提问（按简历自动生成至少 2 题）

| 简历特征 | 大概率被追问 |
|---|---|
| 跳槽 3 次以上 | "每段都不满两年，怎么保证稳定" |
| 有空窗期 | "这段时间在做什么" |
| 职级倒退 | "为什么接受降级" |
| 跨行业转岗 | "之前的经验怎么迁移过来" |
| 项目数据亮眼 | "这个数字是你做的还是团队做的" |
| 前公司知名度低 | "介绍一下你前公司" |
| 技能栏堆砌 | "这个工具你用在哪个项目了，具体怎么用的" |

## 追问链设计

面试官的真实套路是**连环追问**，所以每题后要准备 2 层纵深：

```
表层问题：你负责的项目效果如何？
  ↓ 追问 1：这个结果里，有多少是你的贡献？
  ↓ 追问 2：如果重做一次，你会怎么改？
```

交付时把每题的追问链一并写出，让用户提前想清楚。

## 交给用户的准备建议

- 用 STAR 结构准备 5 个"万能故事"，覆盖：成功、失败、冲突、创新、协作
- 每个故事都能压缩到 1 分钟，也能展开到 5 分钟
- 数字必须能自圆其说（面试官会算）
- 反问环节准备 3 个问题，问业务、问团队、问成长，别问加班和薪资
