# 四类汇报的结构模板

## 一、周报

```
# 本周工作（X 月 X 日 - X 月 X 日）

## 一、本周成果
1. 【项目/事项】做了什么 → 带来什么 → 数据
2. …

## 二、进行中
| 事项 | 进度 | 预计完成 |
|---|---|---|

## 三、问题与需求
- 问题：…（影响：…）
- 需要的支持：…

## 四、下周计划
1. …
```

**周报的三个原则**：
- 成果在前，过程在后（领导只关心结果）
- 一条成果一行，能扫描
- 问题必须带"需要什么支持"，否则等于抱怨

## 二、月报

```
# X 月工作总结

## 一、目标回顾
| 目标 | 目标值 | 实际 | 达成率 |
|---|---|---|---|

## 二、关键成果
1. 【成果】…（数据支撑）
2. …

## 三、问题与偏差分析
- 偏差：…　原因：…　改进：…

## 四、下月重点
1. 【重点】…（预期成果）
```

**与周报的差别**：月报要有**目标 vs 实际**的对照，以及**归因分析**。

## 三、述职报告

```
# 述职报告（X 年 X 月 - X 年 X 月）

## 一、岗位理解
我认为这个岗位的核心价值是…

## 二、关键成果
1. 【成果 A】背景 → 做了什么 → 结果 → 影响
2. 【成果 B】…

## 三、能力成长
- 从…到…
- 掌握/提升了…

## 四、不足与改进
- 不足：…　改进措施：…

## 五、下阶段规划
1. 【目标】…（衡量标准）
```

**述职的关键**：不是罗列做了什么，而是回答"**你在这个位置上创造了什么增量**"。

## 四、项目汇报

```
# 【项目名】进展汇报

## 一、项目目标
（一句话说清要达成什么）

## 二、当前进度
| 阶段 | 计划 | 实际 | 状态 |
|---|---|---|---|

## 三、风险与应对
| 风险 | 影响 | 概率 | 应对措施 |
|---|---|---|---|

## 四、资源需求
- 需要…

## 五、里程碑
| 时间 | 里程碑 | 交付物 |
|---|---|---|
```

**项目汇报的核心**：让领导快速判断**要不要给资源、要不要调整方向**。

## 五、通用写法要点

### 结论先行
```
❌ 因为 A 环节延期了 5 天，所以我们调整了 B 的排期，最终…
✅ 项目延期 3 天，主因是 A 环节延期 5 天，已通过压缩 B 环节追回 2 天。
```

### 一条一事
不要在一段里塞三件事。领导用碎片时间看，一条一行最好。

### 数据必须有参照
```
❌ 转化率 3.2%
✅ 转化率 3.2%，环比提升 0.7 个百分点（目标 3.0%，完成 107%）
```

### 动词要有力
| 弱 | 强 |
|---|---|
| 参与了 | 负责/主导 |
| 协助完成 | 独立完成 |
| 做了一些 | 完成了 X 项 |
| 推进中 | 已完成 X%，预计 X 日完成 |

### 篇幅控制
| 类型 | 建议篇幅 |
|---|---|
| 周报 | 半页到一页 |
| 月报 | 一页 |
| 述职 | 2-3 页（含数据） |
| 项目汇报 | 一页 + 附件 |

## 六、常见减分项

| 减分项 | 问题 |
|---|---|
| 只写过程不写结果 | "参加了 3 次会议"——然后呢？ |
| 全是形容词 | "高效完成了重要工作"——具体是什么？ |
| 没有问题 | 只报喜会显得不真实，也让领导不知道你在哪卡住 |
| 没有下步计划 | 显得被动 |
| 数据无对比 | 单独一个数字说明不了什么 |
| 密不透风 | 一大段不分点，领导没耐心读 |
